## Problem

OpenClaw 2026.9.5 can require substantially longer than 30 seconds for cold Gateway readiness. The CNX lifecycle-start path still used a hardcoded 30-second verification budget even after the surrounding native/shared readiness boundaries had already been updated for the slower 9.5 startup class.

A prior supported install-over reached Host enable, observed only two readiness attempts inside 30 seconds, then failed closed and rolled back to PASSTHROUGH generation 108.

## Repair

`skills/cogentnexus-openclaw/scripts/runtime.py`

now defines:

`LIFECYCLE_START_READY_TIMEOUT_SECONDS = 180.0`

and the lifecycle-start path uses the same bounded value for:

- `wait_for_runtime_health()`;
- emitted `verification.timeoutSeconds`.

No lifecycle-stop timing, Ticket semantics, provider ownership, delivery semantics, or supervisor hard-hang semantics were changed.

## Live blocker evidence

The supported disable path exposed two independent OpenClaw 9.5 compatibility assumptions.

### 1. Removed watchdog schema path

Legacy Host compatibility owns:

`diagnostics.stuckSessionAbortMs`

OpenClaw 2026.9.5 now reports:

`Unknown config path: diagnostics.stuckSessionAbortMs`

while the parent `diagnostics` object remains a valid but unset path.

Therefore the old compatibility fence is no longer a valid host capability on 9.5. Attempting to restore/re-apply that key can fail config validation and contaminate transactional rollback.

### 2. Plugin mutation timeout too short

The transactional disable uses:

`openclaw plugins disable cogentnexus-openclaw`

and rollback may use:

`openclaw plugins enable cogentnexus-openclaw`.

The legacy timeout was `60s` for both operations.

On this host OpenClaw 9.5 cold/lifecycle startup has already been measured around 90.7 seconds. The first CNX-429 installer attempt observed both plugin disable and rollback enable exceed the 60-second budget.

## Required semantics

1. CNX MUST detect whether the watchdog config path is supported before trying to read/write it.
2. If OpenClaw reports `Unknown config path`, watchdog compatibility is retired for that host and CNX MUST perform no set/unset mutation for that path.
3. A valid-but-unset watchdog path on older OpenClaw remains supported and retains the accepted v0.9 behavior.
4. Existing watchdog snapshots MUST remain auditable; unsupported hosts mark the snapshot inactive rather than fabricating a value.
5. Plugin enable/disable mutation must have a bounded timeout large enough for the proven OpenClaw 9.5 lifecycle window.
6. The change MUST NOT alter provider routing, route ownership, Ticket semantics, or normal supervisor recovery.

### Host schema capability

Added `config_path_supported(path)`:

- return supported on successful `config get`;
- return unsupported only for explicit `Unknown config path:`;
- treat `Config path is valid but unset:` as supported;
- fail closed on unrelated CLI/schema errors.

`apply_watchdog_compat` and `restore_watchdog_compat` now skip config mutation when the host removed the path and record auditable `schemaUnsupported` snapshot state.

### Plugin lifecycle timeout

Added:

`PLUGIN_MUTATION_TIMEOUT_SECONDS = 180`

for supported plugin enable/disable mutations.

This aligns the bounded CLI mutation budget with the measured OpenClaw 9.5 lifecycle/startup window without making the operation unbounded.

# CogentNexus v0.8.0

v0.8.0 establishes the **clean Host-managed baseline** for CogentNexus.

This release does not discard the durable runtime introduced earlier; it normalizes architecture, terminology, policy ownership/ordering, lifecycle semantics, installer behavior, delivery semantics, context continuity, platform startup adapters, and public documentation around the external Host Controller and Ticket-first continuity model.

## Baseline rules

- CogentNexus Host owns continuity, selected managed policy, and managed lifecycle behavior outside model inference.
- Eligible owner messages may be committed to durable Tickets before inference.
- Ticket-first durability does not force every request into a heavy workflow.
- Request admission chooses DIRECT / LOOKUP / ACTION / STAGED before heavy CogentNexus references are loaded.
- STAGED work uses the durable controller, deterministic validators, bounded repair/review, checkpoints, and terminal evidence.
- **Execution success is not delivery success:** visible direct replies remain non-terminal until final delivery is confirmed.
- Scheduling a terminal Ticket/workflow continuation does not mark it delivered; the marked delivery turn must itself settle.
- Successful history compaction is not completion; a delayed idempotent continuation guard is scheduled when durable session work remains.
- `cnx stop` means intentional MAINTENANCE.
- `cnx disable` means PASSTHROUGH: CogentNexus relinquishes interception/background ownership and native OpenClaw remains usable.
- The selected managed policy survives PASSTHROUGH and is restored by `cnx enable`.
- A durably accepted request must eventually become delivered/completed, cancelled, or explicitly failed with evidence.

## Cleaned architecture surface

- adds `docs/BASELINE.md` as the canonical current architecture contract;
- rewrites Core README and skill entry point to remove the old "every request enters the runtime" interpretation;
- normalizes workspace `AGENTS` policy so lane admission happens before heavy skill loading;
- adds Host-owned durable managed-policy snapshots and `cnx policy status/register/reset/apply`;
- preserves a registered Ecosystem/companion policy across Core updates and `disable -> enable`;
- documents the historical `cogentnexus-rotation` plugin as the **CogentNexus OpenClaw Bridge** while retaining its ID for compatibility;
- makes source plugin metadata and generated manifest use the same bridge name/description;
- adds a **Delivery Commit Gate** with durable `response_ready_at`, `delivery_confirmed_at`, and delivery-error state;
- uses final reply-dispatch settlement where available and a quiet-period `message_sent` fallback for delivery receipt;
- promotes partial, failed, cancelled, or unconfirmed visible replies to durable recovery instead of silently completing them;
- keeps workflow/Ticket terminal outboxes pending while merely scheduled and retries stale scheduled deliveries after the receipt deadline;
- adds a **Post-Compaction Continuation Guard** that resumes from committed durable state when successful compaction leaves work pending, while cancelling itself if the original run continues normally;
- excludes internal delivery/continuation prompts from new Ticket intake to prevent recursive work creation;
- separates startup policy from Host operating mode;
- normalizes lifecycle semantics around MANAGED / PASSTHROUGH / MAINTENANCE;
- packages macOS launchd Host-supervisor support alongside Windows Task Scheduler and Linux systemd-user startup;
- updates Windows and POSIX installers around Host ownership and enables the OpenClaw conversation-hook access needed for delivery/compaction receipts;
- adds a detailed Thai Windows/OpenClaw/Ollama installation, verification, PASSTHROUGH, cancellation, interruption, and reboot walkthrough;
- marks obsolete Phase 0 behavior as historical rather than current source-of-truth;
- aligns VERSION, package, plugin manifest, lockfile, release validation, and baseline tests.

## Regression coverage

v0.8 includes explicit tests for the two continuity failures that motivated the final delivery/context hardening:

1. a long visible reply becomes `RESPONSE_READY` but is **not** completed until a delivery receipt arrives; partial/failing/no-receipt delivery returns the Ticket to durable recovery;
2. successful compaction while the same session still has durable work schedules one post-compaction continuation, and no continuation is scheduled after the durable work becomes terminal.

Workflow completion and Ticket outbox tests also verify that scheduling alone leaves delivery `pending`, failed delivery becomes retryable, and schema migration upgrades existing Ticket databases through migration v6 without losing accepted work.

## Installation

Windows users should follow [../INSTALL.th.md](../INSTALL.th.md) for the full step-by-step guide.

The standard installer is intended to leave the machine in MANAGED mode with Ticket-first continuity, one inference lane by default, a hidden Host supervisor, a durable selected-policy snapshot, delivery/compaction hooks enabled, and a workspace `cnx.cmd` launcher.

## Validation requirement

Release publication requires Core self-tests, Host/policy tests, delivery/compaction regression tests, baseline consistency tests, plugin tests, deterministic evaluation, production dependency audit, plugin validation, version synchronization checks, installer syntax checks, and package creation to pass.

Historical release notes remain project history. When older descriptions conflict with current architecture language, `docs/BASELINE.md` governs v0.8+.

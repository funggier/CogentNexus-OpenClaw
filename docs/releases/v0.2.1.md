# CogentNexus v0.2.1

This patch release makes runtime recovery observable and reliable on the tested
Windows/OpenClaw installation, and gives the runtime entry point a stable,
meaningful name.

## Runtime recovery fixes

- Gateway health now requires positive connectivity evidence. OpenClaw can
  return exit code `0` from `gateway status` while also reporting `Runtime:
  stopped`, `Connectivity probe: failed`, or `ECONNREFUSED`; CogentNexus now
  treats those states as unhealthy.
- The periodic supervisor therefore detects an unplanned
  `openclaw gateway stop` and invokes bounded Gateway recovery automatically.
- Live acceptance testing confirmed that the hidden one-minute Windows
  watchdog restarted Gateway without a manual `lifecycle start` command.
- Recovery remains fenced during intentional maintenance. `lifecycle stop`
  writes a manual maintenance marker and does not trigger an unwanted restart.

## Startup readiness

- `lifecycle start --provider` is still idempotent and skips already healthy
  components.
- After requesting Gateway startup, it now polls Gateway and provider readiness
  for up to 30 seconds instead of relying on one early probe.
- This covers normal Gateway warm-up and removes the previous need to issue the
  start command a second time.
- Verification output includes attempt count, timeout, and initial delay.

## Runtime naming

- `scripts/runtime.py` is now the canonical entry point for lifecycle,
  supervisor, concurrency, context, scheduler, and runtime configuration.
- CLI help identifies it as `cogent-runtime`.
- Scheduler templates, lifecycle launchers, installers, CI, and documentation
  use `runtime.py`.
- `phase3.py` remains as a deprecated compatibility shim so existing commands
  continue to work during migration.

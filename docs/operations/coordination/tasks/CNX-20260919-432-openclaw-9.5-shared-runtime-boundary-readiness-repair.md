## Root cause

`openclaw_runtime_boundary_v092.activate_current_config()` performed:

1. `openclaw gateway restart` (fallback `start`);
2. one immediate `openclaw gateway status`;
3. fail if that single status was not fully healthy.

OpenClaw 2026.9.5 cold startup is known on this host to require tens of seconds after process start before WebSocket/connectivity health is ready.

The shared boundary therefore repeated the same single-shot readiness assumption already repaired at the Host-native layer by CNX-431.

## Required semantics

1. Gateway restart/start remains bounded.
2. The shared runtime boundary waits through transient OpenClaw 9.5 startup states.
3. Per-status probe timeout is bounded.
4. Total readiness wait is bounded to 180 seconds.
5. Success requires the same existing strict health predicate:
   - Runtime running;
   - Connectivity probe ok;
   - no negative transport markers.
6. Expired readiness budget fails closed.
7. Readiness evidence is returned to the caller.
8. No provider selection/routing, Ticket, recovery, delivery, or ownership semantics change.

## Production repair

Changed:

`skills/cogentnexus-openclaw/scripts/openclaw_runtime_boundary_v092.py`

Added:

- `GATEWAY_READY_TIMEOUT_SECONDS = 180.0`
- `GATEWAY_READY_POLL_SECONDS = 2.0`
- `GATEWAY_STATUS_PROBE_TIMEOUT_SECONDS = 20`
- `_wait_gateway_ready()`

The waiter:

- repeatedly executes `openclaw gateway status`;
- keeps each probe <=20 seconds;
- keeps the total readiness budget <=180 seconds;
- reuses the existing strict `_healthy_status()` predicate;
- returns attempts, elapsed time, probe timeout and last status;
- fails closed after budget exhaustion.

`activate_current_config()` now consumes this bounded waiter rather than one immediate status probe.

Historical test `test_unhealthy_post_boundary_status_fails_closed` was adapted to mock the bounded-wait result so unit tests do not sleep for 180 seconds.

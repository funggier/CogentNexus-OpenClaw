# CogentNexus v0.8.0

v0.8.0 establishes the **clean Host-managed baseline** for CogentNexus.

This release does not discard the durable runtime introduced earlier; it normalizes the architecture, terminology, policy ordering, installer behavior, and public documentation around the external Host Controller and Ticket-first continuity model.

## Baseline rules

- CogentNexus Host owns continuity and managed lifecycle behavior outside model inference.
- Eligible owner messages may be committed to durable Tickets before inference.
- Ticket-first durability does not force every request into a heavy workflow.
- Request admission chooses DIRECT / LOOKUP / ACTION / STAGED before heavy CogentNexus references are loaded.
- STAGED work uses the durable controller, deterministic validators, bounded repair/review, checkpoints, and terminal evidence.
- `cnx stop` means intentional MAINTENANCE.
- `cnx disable` means PASSTHROUGH: CogentNexus relinquishes interception/background ownership and native OpenClaw remains usable.
- A durably accepted request must eventually become delivered/completed, cancelled, or explicitly failed with evidence.

## Cleaned architecture surface

- adds `docs/BASELINE.md` as the canonical current architecture contract;
- rewrites the Core README and skill entry point to remove the old "every request enters the runtime" interpretation;
- normalizes workspace `AGENTS` policy so lane admission happens before heavy skill loading;
- documents the historical `cogentnexus-rotation` plugin as the CogentNexus OpenClaw Bridge while retaining its ID for compatibility;
- separates startup policy from Host operating mode;
- normalizes lifecycle semantics around MANAGED / PASSTHROUGH / MAINTENANCE;
- adds a detailed Thai Windows installation and recovery walkthrough;
- aligns release/version validation and baseline tests.

## Installation

Windows users should follow [../INSTALL.th.md](../INSTALL.th.md) for the full step-by-step guide.

The standard installer is intended to leave the machine in MANAGED mode with Ticket-first continuity, one inference lane by default, a hidden Host supervisor, and a workspace `cnx.cmd` launcher.

## Validation requirement

Release publication requires Core self-tests, Host tests, baseline consistency tests, plugin tests, deterministic evaluation, production dependency audit, plugin validation, version checks, and package creation to pass.

Historical release notes remain unchanged as project history; when older descriptions conflict with current architecture language, `docs/BASELINE.md` governs v0.8+.

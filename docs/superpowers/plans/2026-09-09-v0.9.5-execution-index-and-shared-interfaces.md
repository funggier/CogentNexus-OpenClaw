# v0.9.5 Execution Index and Shared Interface Contract

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. This document is the execution index for the four v0.9.5 subsystem plans and resolves shared interface naming across them.

**Goal:** Execute v0.9.5 in a dependency-safe order with one shared vocabulary for Host state, inference attempts, delivery attempts, session generation, local adapters, and Supervisor wake authority.

**Architecture:** Provider/runtime repair establishes authority boundaries first. Delivery/session identity builds on that stable boundary. Supervisor single-wake then consumes canonical delivery/provider/session authority. Migration/matrix/release runs last and is not allowed to compensate for unfinished subsystem behavior.

**Tech Stack:** Python 3, TypeScript, SQLite, Vitest, unittest, OpenClaw, GitHub Actions, Windows lifecycle acceptance.

**Specs:**
- `docs/superpowers/specs/2026-09-09-v0.9.5-architecture-repair-design.md`
- `docs/superpowers/specs/2026-09-09-v0.9.5-local-provider-command-contract.md`
- `docs/superpowers/specs/2026-09-09-v0.9.5-idle-quiescence-and-single-wake-contract.md`

## 12. Cross-plan non-regression rules

- Plan 1 must not redesign delivery.
- Plan 2 must not reintroduce provider selection into Ticket/Session identity.
- Plan 3 must consume canonical delivery/local-provider/session authority rather than duplicate it.
- Plan 4 must not patch around an unfinished subsystem merely to make acceptance pass.
- No task may introduce another recurring poller without amending the idle-quiescence spec and proving why the canonical Supervisor cannot own the condition.
- No task may weaken ambiguous/stale delivery fail-closed behavior.
- No task may force push.

# CogentNexus-OpenClaw v0.9.3

CogentNexus-OpenClaw v0.9.3 **กำหนดชื่อเรียกและ namespace ของแต่ละส่วนให้ชัดเจน** เพื่อให้ launcher, skill, plugin, state/config root, tools, tasks/services, packages, release artifacts, reset และ uninstall ระบุ OpenClaw product variant อย่างอ่านเข้าใจได้ทันที และอยู่ร่วมกับ CogentNexus-HermesAgent ได้โดยไม่ชนกัน

## Breaking namespace migration

This release intentionally breaks the pre-1.0 generic namespace. It is an API and installation-layout migration, not a cosmetic rename. The command is now `cnxclaw`, state lives under `.cogentnexus-openclaw`, and the skill, plugin, tools, service identities, package, policy, and archives all use the `cogentnexus-openclaw` or `CNXCLAW` namespace.

Installation over a legacy deployment is transactional: the installer inventories the old and new layouts, proves legacy ownership from multiple independent identities, enters native/PASSTHROUGH once when required, creates a versioned backup, stages and validates the new namespace and ownership manifest, then removes legacy registrations and files only after the replacement is usable. Ambiguous, mixed, corrupted, or foreign layouts fail closed.

Permanent generic aliases such as `cnx.cmd`, `cnx`, `skills/cogentnexus`, `.cogent`, and `cogentnexus-rotation` are not retained after a successful migration.

Reset, repair, upgrade, and uninstall require a matching ownership manifest. They remove only CogentNexus-OpenClaw-owned artifacts and preserve OpenClaw, Ollama, unrelated workspace data, and every CogentNexus-HermesAgent namespace.

Historical coordination evidence and older release notes retain their original names because rewriting them would falsify the published record.

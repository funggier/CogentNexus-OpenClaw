# CogentNexus v0.9.0

## Intent and Session Boundary Foundation

v0.9.0 establishes two authoritative boundaries:

1. human cancellation outranks automatic recovery; and
2. cross-session visibility never implies cross-session ownership.

Mutable execution state is owned by an exact OpenClaw session and a CogentNexus session generation. Read-only context may be sourced from other sessions, but that does not transfer or merge ownership.

### Current guarantees

- An explicit user-abort classification cancels the active Ticket and every queued/non-terminal Ticket owned by the exact OpenClaw session, without mutating another session.
- UI Stop is a generation boundary. It advances only that session's CogentNexus generation, cancels session-owned work, suppresses pending delivery and Direct Recovery, and rejects late results from the previous generation.
- UI Reset creates a new generation on the same session key. Mutable work from the previous generation is cancelled and cannot cross into the reset context; the session key remains usable for fresh work.
- UI Delete revokes execution authority before cleanup, cancels session-owned Tickets/workflows/recovery/delivery, and then tombstones the CogentNexus session as `deleted`. Durable Ticket/audit history keeps the original owner-session provenance.
- Creating a distinct new session does not implicitly transfer Ticket, workflow, outbox, recovery, or synthetic-run ownership from the old session.
- Bound workflows are cancelled through the durable workflow cancellation path; pending workflow completion wakes for a revoked session are suppressed and unscheduled.
- Cancelled Tickets are terminal and silent: cancellation does not enqueue another model-facing terminal Outbox turn.
- Failed, blocked, and cancelled terminal states remain queryable durable truth but do not wake inference merely to announce failure.
- Pending Direct Recovery state for terminal Tickets is fenced before managed startup so stale recovery cannot resurrect completed, failed, or cancelled work.
- The exact legacy `Reply operation aborted by user` state and the installed OpenClaw abort rendering are migrated/classified as cancellation rather than reopened permanent failure.
- Synthetic recovery and compatibility-delivery inference run in hidden `:subagent:` sessions, never in the owner session. Only bounded read-only owner context is copied into the hidden worker.
- Internal CogentNexus control prompts are blocked at owner-session `before_agent_run` and `before_message_write` boundaries as defense in depth.
- User-facing synthetic results are queued durably and delivered to the exact owner session as gateway-authored assistant messages through OpenClaw `chat.inject`; delivery does not require another owner-session inference turn.
- Assistant delivery is session-isolated: ordering is preserved within one session, while an unavailable Session A cannot block Session B's delivery queue.
- Delivery/recovery carries the captured owner generation. A result or timer created before Stop/Reset/Delete cannot settle after the generation changes.
- Workflow deduplication is scoped to the exact owner session. Identical prompts in different sessions never silently share workflow ownership.
- Shared workspace writes are separately conflict-fenced. Session isolation does not permit two workflows to concurrently claim the same named output resource.
- Generic provider interruption remains recoverable; v0.9.0 does not guess that every interruption is a user cancellation.
- Host Gateway health requires observed `Runtime: running` and a successful connectivity probe; a zero OpenClaw CLI exit code alone is not treated as healthy.

### OpenClaw UI lifecycle integration

The installed OpenClaw 2026.7.1-2 lifecycle is used rather than inferred from transcript disappearance:

- exact dashboard session keys are treated as ownership identities;
- `session_end: reset` and same-key new-generation transitions revoke the old CogentNexus generation;
- `session_end: deleted` runs the deletion barrier and creates a durable session tombstone;
- distinct new dashboard sessions remain independent ownership domains.

OpenClaw's own session lifecycle admission around `chat.inject` also revalidates the target session/session-id before transcript mutation. CogentNexus adds its own generation check before and after durable delivery settlement so OpenClaw lifecycle protection and CogentNexus durable authority agree.

### Multi-session model

Session-local mutable state includes Ticket ownership, Direct Recovery, pending delivery, synthetic runs, scheduled continuation, cancellation generation, and session-owned workflows. These never transfer merely because another session can read their history.

Cross-session context is read-only provenance. If Session B reads Session A, work created by B is still owned by B. Shared/project state requires an explicit ownership model rather than accidental session reuse.

Session deletion therefore means:

`revoke authority -> advance generation -> cancel/suppress session-owned work -> verify/cancel native synthetic execution -> tombstone session`

It does **not** mean `delete -> transfer to another session`.

### Live-test failures motivating this release

v0.8.4 testing demonstrated that an OpenClaw Control UI Stop could be reduced to an interruption and then recovered repeatedly. Initial v0.9.0 live testing exposed additional boundaries:

- cancelling a Ticket could create a pending terminal Outbox and model-facing synthetic delivery;
- a synthetic delivery run could survive UI Stop;
- OpenClaw native orphan recovery could resurrect a stale `cnx-scheduled-*` task even when CogentNexus Ticket/Outbox/Direct-Recovery state was already terminal;
- the first native-task fence bound only an agent-level/main session and therefore missed the exact dashboard session;
- internal `[CogentNexus Delivery: ...]` prompts could be written as owner-session user turns;
- prompt-hash workflow deduplication could incorrectly reuse work across different owner sessions.

The native-task fence now preserves exact `owner_session_key`, while the session-generation and hidden-worker architecture removes the broader class of owner-session synthetic execution leaks.

The same live test showed that `openclaw gateway status` may return exit code 0 while reporting `Runtime: stopped` and a failed connectivity probe. CogentNexus therefore no longer derives Gateway health from process exit status alone.

### Validation checkpoint

The previous validated candidates remain historical evidence only; they are not the current live-test candidate after session-ownership hardening.

Current validation includes Windows, Ubuntu, and macOS across Python 3.11 and 3.14; Python Host tests; multi-session assistant-delivery tests; TypeScript session ownership/generation tests; plugin evaluation; dependency audit; and OpenClaw plugin contract validation. An exact candidate SHA will be recorded here only after the full matrix passes and before the next Windows live test.

### Known follow-up hardening

This release does not yet claim verified provider-request termination for every possible OpenClaw/provider execution path. Provider cancellation ownership, wider fault injection, context-budgeted continuation, and the separate interactive-terminal/stdin boundary remain follow-up work before v1.0.0.

The installed OpenClaw 2026.7.1-2 contract does not expose a dedicated `chat_abort` plugin hook. Direct UI abort is therefore classified narrowly from the observed OpenClaw abort termination, while restart/provider interruption remains distinct. Generic `interrupted` alone is intentionally not treated as user cancellation because doing so would disable crash recovery.

# CogentNexus v0.9.0

## Intent Boundary Foundation

v0.9.0 establishes the first explicit rule that human cancellation outranks automatic recovery.

### Current guarantees

- An explicit user-abort classification cancels the active Ticket and every queued/non-terminal Ticket owned by the same OpenClaw session.
- Cancelled Tickets are terminal and are excluded from Direct Recovery and normal dispatch.
- Pending Direct Recovery state for cancelled Tickets is suppressed instead of being resurrected.
- The exact legacy `Reply operation aborted by user` state is migrated to `cancelled` rather than reopened.
- Direct Recovery prompts use the CogentNexus Continuation namespace so synthetic recovery traffic is excluded from human Ticket intake.
- Generic provider interruption remains recoverable; v0.9.0 does not guess that every interruption is a user cancellation.

### Live-test failures motivating this release

v0.8.4 testing demonstrated that an OpenClaw Control UI Stop could be reduced to an interruption and then recovered repeatedly. It also exposed repeated terminal delivery, synthetic-message provenance ambiguity, and provider/lifecycle coupling that require stronger intent boundaries.

### Known follow-up hardening

This baseline does not claim that cancellation has already propagated to every detached workflow or provider process. Physical worker/provider cancellation with verified termination, terminal outbox ACK/redelivery hardening, and the root cause of synthetic text reaching an interactive terminal remain follow-up work before v1.0.0.

OpenClaw currently does not expose a dedicated `chat_abort` plugin hook in the plugin contract inspected for this work, so Control UI Stop integration must be verified against the termination metadata emitted by the installed OpenClaw build. Generic `interrupted` alone is intentionally not treated as user cancellation because doing so would disable crash recovery.

# v0.9.5 Delivery and Session Identity Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace fragmented Direct/Durable delivery correlation with canonical inference-attempt and delivery-attempt identities while preserving exact owner-session/generation safety across Web Chat and Discord.

**Architecture:** Ticket and logical Session identities remain stable across provider changes. Each inference retry gets its own attempt identity; each final-payload delivery attempt gets its own durable identity. Surface hooks become adapters that submit evidence to one Delivery Core rather than implementing settlement policy independently.

**Tech Stack:** TypeScript, Node SQLite bindings, OpenClaw plugin hooks, Vitest, Python Host delivery/recovery helpers.

**Spec:** `docs/superpowers/specs/2026-09-09-v0.9.5-architecture-repair-design.md`

## Global Constraints

- Never guess the latest run in a session.
- Ambiguous delivery evidence cannot complete a Ticket.
- Duplicate callbacks are idempotent no-ops.
- Stale generation evidence fails closed.
- Provider/model are metadata of inference attempts, never Ticket/Session identity.
- Durable final payload must suppress unnecessary inference regeneration.
- Web Chat and Discord use one completion policy.
- Preserve existing v0.9.4 Discord wrong-settlement protections.

### Task 2: Implement canonical DeliveryAttempt state machine

**Interfaces:**

```ts
export type DeliveryState = "prepared" | "staged" | "transport_accepted" | "confirmed" | "failed" | "cancelled";

export function prepareDelivery(db: DatabaseSync, input: PrepareDeliveryInput): DeliveryAttempt;
export function stageDelivery(db: DatabaseSync, attemptId: string, evidence: DeliveryEvidence): DeliveryAttempt;
export function acceptTransport(db: DatabaseSync, attemptId: string, evidence: DeliveryEvidence): DeliveryAttempt;
export function confirmDelivery(db: DatabaseSync, attemptId: string, evidence: DeliveryEvidence): DeliveryAttempt;
export function findExactDelivery(db: DatabaseSync, key: ExactDeliveryKey): DeliveryAttempt | null;
```

Exact key includes Ticket, run when available, owner session, owner generation, surface, payload hash/idempotency key.

- [ ] **Step 1: Write RED state-machine tests**

Cover:

```text
prepared -> staged -> transport_accepted -> confirmed
same callback twice -> same row/state
wrong generation -> rejected/no transition
missing exact identity -> no confirmation
same Ticket/payload/generation -> stable idempotency authority
```

- [ ] **Step 4: Implement deterministic transition guards**

# CogentNexus v0.9.0

## Intent Boundary Foundation

v0.9.0 establishes the first explicit rule that human cancellation outranks automatic recovery.

### Current guarantees

- An explicit user-abort classification cancels the active Ticket and every queued/non-terminal Ticket owned by the same OpenClaw session.
- UI Stop is treated as a session cancellation boundary: pending Ticket delivery and Direct Recovery owned by that session are suppressed even when the active OpenClaw run is synthetic delivery rather than the original human Ticket run.
- Bound workflows are cancelled through the existing durable workflow cancellation path; pending workflow completion wakes for the cancelled session are suppressed and unscheduled.
- Cancelled Tickets are terminal and silent: cancellation does not enqueue another model-facing terminal Outbox turn.
- Pending Direct Recovery state for terminal Tickets is fenced before managed startup so stale recovery cannot resurrect completed, failed, or cancelled work.
- The exact legacy `Reply operation aborted by user` state is migrated to `cancelled` rather than reopened.
- Direct Recovery prompts use the CogentNexus Continuation namespace so synthetic recovery traffic is excluded from human Ticket intake.
- Generic provider interruption remains recoverable; v0.9.0 does not guess that every interruption is a user cancellation.
- Host Gateway health now requires observed `Runtime: running` and a successful connectivity probe; a zero OpenClaw CLI exit code alone is not treated as healthy.

### Live-test failures motivating this release

v0.8.4 testing demonstrated that an OpenClaw Control UI Stop could be reduced to an interruption and then recovered repeatedly. Initial v0.9.0 live testing then exposed a second boundary failure: cancelling a Ticket created a pending `cancelled` terminal Outbox, and UI Stop on that synthetic delivery did not suppress the session's durable delivery/recovery state. The old dashboard session consequently retried model-facing synthetic work and could hit model context overflow.

The same live test also showed that `openclaw gateway status` may return exit code 0 while reporting `Runtime: stopped` and a failed connectivity probe. CogentNexus therefore no longer derives Gateway health from process exit status alone.

### Known follow-up hardening

This release does not yet claim verified provider-request termination for every possible OpenClaw/provider execution path. Provider cancellation ownership, terminal delivery idempotency under wider fault injection, context-budgeted continuation, and the root cause of synthetic text reaching an interactive terminal remain follow-up work before v1.0.0.

OpenClaw currently does not expose a dedicated `chat_abort` plugin hook in the plugin contract inspected for this work. For the installed OpenClaw 2026.7.1-2 behavior tested here, direct UI abort is classified narrowly from the exact `agent run aborted` termination while restart abort remains distinct. Generic `interrupted` alone is intentionally not treated as user cancellation because doing so would disable crash recovery.

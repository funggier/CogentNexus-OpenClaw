## OpenClaw 2026.9.6 convergence defect and repair

The first post-upgrade MANAGED activation exposed a bounded compatibility gap in CogentNexus `scripts/runtime.py`: the inner native `openclaw gateway restart` command used a hard-coded 60-second subprocess budget even though the outer Host activation already allowed 240 seconds.

Observed evidence:
- the pre-repair activation reached the MANAGED linearization point, then the inner Gateway restart exceeded 60 seconds;
- the transactional enable path failed closed and restored healthy native PASSTHROUGH rather than leaving partial MANAGED authority;
- the same OpenClaw 2026.9.6 restart later completed successfully in `128801 ms`;
- therefore the 60-second inner budget was shorter than real 2026.9.6 cold-start convergence on this host.

Repair:
- add `LIFECYCLE_RESTART_COMMAND_TIMEOUT_SECONDS = 180.0`;
- use that bounded value for the native Gateway restart command;
- preserve the existing maintenance marker, supervisor recovery policy, Host transaction, rollback path, and outer 240-second lifecycle budget;
- add `tests/test_v096_gateway_restart_timeout.py` to pin the 180-second contract.

After the repair, official `host_control_v092.py enable` completed transactionally with `mode=managed`, generation `54`, native restart success, verified Gateway health, verified Ollama health, and no post-commit recovery error.

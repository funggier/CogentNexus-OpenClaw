The second supported install-over attempt for the CNX-429 candidate passed both CNX-430 compatibility defects:

- the old 60-second plugin mutation timeout was no longer the terminal blocker.

## Root cause

`host_v091_legacy_v094.py::_restore_native_gateway()` performed:

1. `openclaw gateway restart` (or fallback `start`);
2. exactly one immediate `gateway_status()` probe;
3. immediate failure when that single probe was not healthy.

That assumption is invalid for OpenClaw 2026.9.5 because service startup can expose process/service state before full Gateway readiness.

This is a readiness race, not evidence that the Gateway process failed to start.

## Required semantics

1. Native Gateway restart/start remains bounded.
2. A successful restart/start command must not be treated as immediately ready.
3. CNX must tolerate transient `ECONNREFUSED`, `ETIMEDOUT`, or unready status during the documented OpenClaw 9.5 cold-start window.
4. Readiness polling must be bounded; no infinite wait is allowed.
5. The boundary commits PASSTHROUGH only after a genuinely healthy Gateway status.
6. If the bounded readiness window expires, the transaction still fails closed.
7. No provider routing, Ticket semantics, delivery semantics, or supervisor hard-hang behavior is changed.

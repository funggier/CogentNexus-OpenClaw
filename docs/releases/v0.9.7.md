# CogentNexus-OpenClaw v0.9.7

Status: **development candidate — not yet published**

v0.9.7 is a continuity/recovery bug-fix line for exact Direct recovery when a confirmed OpenClaw Gateway process replacement interrupts an in-flight model call.

## Why this release exists

A production Discord turn on OpenClaw 2026.9.5 exposed a gap that v0.9.6 did not close:

1. CogentNexus-OpenClaw durably accepted the Ticket.
2. OpenClaw started the selected model call on `ollama/qwen3.8:27b`.
3. The external Host confirmed the Gateway was unresponsive.
4. The Gateway process was restarted while the model call was still in flight.
5. Because the old process disappeared, neither `model_call_ended` nor a failing `agent_end` persisted terminal model-call evidence.
6. The CNX model-call row therefore remained `active`.
7. Provider-neutral safety correctly suppressed timer-only destructive recovery.
8. The Ticket became stranded until OpenClaw's whole-run timeout expired.

The incident proved that a Gateway process boundary needs its own exact recovery evidence.

## Exact Gateway-interruption recovery

v0.9.7 changes confirmed hard-hang recovery from a single opaque Gateway restart into an ordered Host boundary:

```text
confirmed hard hang
  -> prepare recoverable maintenance
  -> stop/quiesce Gateway
  -> classify eligible active Direct calls as interrupted
  -> persist exactly-one pending Direct recovery per eligible Ticket
  -> start replacement Gateway
  -> startup liveness wakes Direct Recovery
```

Classification occurs only while Gateway inference is quiesced.

v0.9.7 also covers a Gateway replacement initiated outside the exact hard-hang call site. The Host resolves the live Gateway PID to its `gateway_boot_lifecycle` row, identifies the immediately preceding boot, and only treats active Direct calls started inside that predecessor boot window as orphaned. Calls from older Gateway generations are historical residue and are not replayed automatically.

The Host records gateway-specific evidence:

- event: `host_direct_model_gateway_interruption_authorized`;
- model-call outcome: `host-gateway-interruption-authorized`;
- recovery authority: `gateway-interruption`.

This evidence is intentionally distinct from timer/deadline recovery.

### Exact generation scoping

Gateway-interruption authority is scoped to exact Direct-call identities captured from the Gateway generation being replaced. The Host snapshots current-generation `{ticket_id, call_id}` identities before quiescence and passes that evidence into the post-stop classifier.

The classifier treats that evidence as an allow-list. Older `active` rows from historical incidents are not automatically replayed merely because the Gateway is being replaced. This prevents a new hard-hang from reviving unrelated stale work.

### Detached embedded recovery on OpenClaw 2026.9.5

OpenClaw 2026.9.5 tightened plugin async-action session ownership. The older Direct Recovery compatibility layer still supplied a temporary filesystem `session.jsonl` target, which OpenClaw now rejects before inference with a SQLite transcript-marker ownership error.

v0.9.7 now runs the isolated embedded recovery helper with `sessionPersistence: "detached"` and no legacy `sessionFile`. The existing internal `:subagent:` session-key fence remains in place. Detached recovery can use session identity for policy resolution while writing no durable helper transcript or session metadata.

CogentNexus-OpenClaw does not synthesize or bypass OpenClaw's SQLite ownership markers.

## What v0.9.7 does not change

The 15-minute CNX model-call deadline remains **observational only**.

A healthy Gateway/provider plus an elapsed deadline does **not** authorize:

- model cancellation;
- Gateway restart;
- provider restart;
- replacement inference.

This is required because slow local models may validly run longer than 15 minutes. Earlier physical qualification observed a successful Qwen run lasting roughly 44 minutes 43 seconds.

OpenClaw still owns:

- provider/model selection;
- Cloud authentication;
- provider routing;
- provider runtime lifecycle.

CogentNexus-OpenClaw continues to own continuity, Ticket/session/generation state, recovery evidence, Gateway lifecycle boundaries, and verified delivery.

## Recovery fences preserved

Gateway-interruption recovery does not regenerate work when durable evidence already shows that inference must not repeat.

The existing fences remain authoritative for:

- `response_ready`;
- confirmed/durable Direct result delivery;
- terminal/cancelled Ticket state;
- workflow-owned work;
- owner session/generation authority.

## Failure safety

If Gateway stop/quiescence succeeds but interruption classification fails, the Host attempts bounded Gateway restoration before surfacing the failure. The repair must not strand the machine in an intentional maintenance state.

OpenClaw 2026.9.5 also requires explicit `--force` authority before stopping the operator's registered Gateway service. v0.9.7 therefore forwards force only from the two exact CNX recovery boundaries that have already established Gateway replacement authority: confirmed hard-hang replacement and exact current-boot orphan reconciliation. Ordinary lifecycle stop remains non-force unless the caller explicitly requests it.

# CogentNexus-OpenClaw v0.9.5

> **Publication status: unreleased.** This document describes the reviewed v0.9.5 release candidate and its release gates. It is not evidence that a GitHub Release or `v0.9.5` tag has been published.

## What changed

v0.9.5 consolidates the provider/runtime, session/delivery, and Supervisor idle-repair work into one provider-independent continuity contract.

### Provider ownership remains with OpenClaw

CogentNexus-OpenClaw does not take ownership of OpenClaw provider authentication, model selection, or provider routing. Cloud routes remain OpenClaw-owned pass-through, while managed local-provider lifecycle remains explicitly bounded.

### Session and delivery identity is canonical

Lifecycle identity is bound to the physical session lifecycle through `sessionKey + sessionId + generation`. Delivery identity is fenced by Ticket, inference attempt/run identity, owner session/generation, surface, payload hash, and idempotency key. Stale-generation delivery and ambiguous Discord receipt identity fail closed.

### Idle Supervisor is single-wake and quiescent

The v0.9.5 wake authority separates actionable durable work from ordinary idle cadence. With no actionable work, the lightweight idle path must not invoke heavyweight Supervisor recovery, provider recovery, configuration mutation, or Gateway lifecycle actions.

### v0.9.4 migration is explicit

The upgrade boundary preserves CNX durable state while keeping OpenClaw-owned route/auth/model configuration outside CNX migration authority. The supported migration set is the reviewed v0.9.4 state shape.

### Local Ollama command namespace

Current managed local-provider operations use the CogentNexus-OpenClaw operator namespace without changing OpenClaw's provider/model/auth routing ownership.

## Release-gate evidence

## Compatibility boundary

- Validated OpenClaw baseline remains `2026.7.1-2` for this release line.
- Unsupported or unverified newer OpenClaw behavior remains outside the release guarantee.
- Real abrupt power-loss/cold-boot acceptance, high-concurrency/long-soak hardening, disk-full/DB-corruption recovery, and exactly-once arbitrary external side effects remain outside the accepted release guarantee unless separately evidenced.

# v0.9.5 Delivery and Session Identity Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace fragmented Direct/Durable delivery correlation with canonical inference-attempt and delivery-attempt identities while preserving exact owner-session/generation safety across Web Chat and Discord.

**Architecture:** Ticket and logical Session identities remain stable across provider changes. Each inference retry gets its own attempt identity; each final-payload delivery attempt gets its own durable identity. Surface hooks become adapters that submit evidence to one Delivery Core rather than implementing settlement policy independently.

**Tech Stack:** TypeScript, Node SQLite bindings, OpenClaw plugin hooks, Vitest, Python Host delivery/recovery helpers.

**Spec:** `docs/superpowers/specs/2026-09-09-v0.9.5-architecture-repair-design.md`

## Global Constraints

- Never guess the latest run in a session.
- Ambiguous delivery evidence cannot complete a Ticket.
- Duplicate callbacks are idempotent no-ops.
- Stale generation evidence fails closed.
- Provider/model are metadata of inference attempts, never Ticket/Session identity.
- Durable final payload must suppress unnecessary inference regeneration.
- Web Chat and Discord use one completion policy.
- Preserve existing v0.9.4 Discord wrong-settlement protections.

```ts
export type SessionGenerationCause = "delete" | "replace" | "rotate" | "provider_change" | "model_change" | "compaction" | "gateway_restart";
export function shouldAdvanceSessionGeneration(cause: SessionGenerationCause, samePhysicalSession: boolean): boolean;
```

```ts
if (cause === "delete" || cause === "replace" || cause === "rotate") return !samePhysicalSession;
```

`v090.ts` remains the durable owner of `cnx_sessions`; the new module only centralizes the decision rule so no second session store is introduced.

## Compatibility and provider boundary

- validated OpenClaw baseline: `2026.7.1-2 (0790d9f)`;
- current managed provider: **Ollama only**;
- the installer is provider-neutral and does not own runtime provider selection/preflight;
- historical v0.9.2 LM Studio support remains historical compatibility/migration knowledge only and is not a v0.9.3 operator promise;
- unsupported provider names fail closed rather than silently falling back.

The package peer range may be broader for installation compatibility, but the operational guarantee for v0.9.3 is no broader than the tested OpenClaw baseline above unless separate evidence explicitly qualifies another version.

## Breaking namespace migration

v0.9.3 intentionally breaks the pre-1.0 generic namespace. It is an API and installation-layout migration, not a cosmetic rename.

Current identities include:

- launcher/CLI: `cnxclaw` / `cnxclaw.cmd`;
- state root: `.cogentnexus-openclaw`;
- skill: `skills/cogentnexus-openclaw`;
- plugin: `cogentnexus-openclaw`;
- package: `openclaw-plugin-cogentnexus-openclaw`;
- service/task identities: CogentNexus-OpenClaw-specific;
- release archives: `cogentnexus-openclaw-v0.9.3.*`.

Permanent generic aliases such as `cnx.cmd`, `cnx`, `skills/cogentnexus`, `.cogent`, and `cogentnexus-rotation` are not retained after successful migration.

The namespace is designed to coexist with future/parallel CogentNexus product variants such as CogentNexus-HermesAgent without ownership collisions.

## Ownership-safe install and upgrade

Installation over an existing deployment is transactional and fail-closed:

1. inventory current/new/legacy product surfaces before mutation;
2. recover only a valid, marker-authorized incomplete fresh-install transaction;
3. prove plugin/package identity before mutation;
4. move an existing managed deployment to native/PASSTHROUGH before replacing controlled surfaces;
5. stage/validate the new skill and plugin;
6. create and verify exact ownership metadata;
7. enable MANAGED only after installation-owned postconditions pass.

Ambiguous, mixed, corrupted, or foreign layouts are not adopted or deleted automatically.

## Provider-neutral installer, Ollama-only runtime

The installer no longer binds provider policy that it does not need. Provider selection/readiness belongs to runtime/configuration layers.

The v0.9.3 operator/runtime surface manages Ollama only:

```powershell
.\cnxclaw.cmd start
.\cnxclaw.cmd start --provider ollama
.\cnxclaw.cmd restart
.\cnxclaw.cmd check provider
.\cnxclaw.cmd check provider ollama
```

LM Studio installations on the machine are left untouched.

## Ticket-first durable intent and Direct execution

Eligible owner input is durably admitted as a Ticket before inference while ordinary conversational work can remain in the lightweight DIRECT lane rather than being forced into a heavyweight workflow.

Durable authority is fenced by Ticket/session/generation/runtime state. A transient process observation or transient SQLite BUSY read is not allowed to silently revoke Host ownership and create duplicate inference.

## Single-owner recovery and native restart fencing

For a genuinely pre-response interrupted Direct call, Host-authorized Direct Recovery preserves the owner session/generation and original provider/model provenance.

OpenClaw native restart continuation is consumed only when durable evidence proves that the exact continuation belongs to the same CNX-owned recovery. Ordinary user prompts and unproven native behavior are not globally suppressed.

Elapsed time alone is not recovery authority.

## Durable result and delivery boundary

`response_ready` and the durable Direct result are evidence boundaries. Once an exact durable result exists:

- delivery transport may retry that exact result;
- inference must not be regenerated merely because delivery is uncertain;
- completed/cancelled/failed Tickets remain fenced against stale workers;
- possible external side effects require idempotency/receipt/read-after-write evidence before repetition.

CogentNexus-OpenClaw provides an exactly-once-ish durable delivery boundary for its owned delivery path, not a universal exactly-once guarantee for arbitrary external systems.

## Read-only preflight

Current diagnostic surface includes:

```powershell
.\cnxclaw.cmd check system
.\cnxclaw.cmd check provider
.\cnxclaw.cmd check gateway
.\cnxclaw.cmd check model
.\cnxclaw.cmd check storage
.\cnxclaw.cmd check recovery
.\cnxclaw.cmd check delivery
.\cnxclaw.cmd check resources
```

Checks are observational. They must not start/restart runtime components, repair state, rewrite configuration, mutate the Ticket database, or execute model inference.

System verdicts are:

- `READY` (0)
- `READY_WITH_WARNINGS` (1)
- `NOT_READY` (2)
- `INDETERMINATE` (3)

## Reset and uninstall

There is intentionally no `cnxclaw install` command. Installation is performed from the source/release archive installer.

Destructive lifecycle commands require explicit `y` confirmation:

```powershell
.\cnxclaw.cmd reset
.\cnxclaw.cmd uninstall
```

`reset` clears/reconstructs only CogentNexus-OpenClaw-owned state to a fresh-install state.

`uninstall` returns to native/PASSTHROUGH and removes only CogentNexus-OpenClaw-owned surfaces. External OpenClaw, Ollama runtimes/models/data, unrelated workspace data, and unrelated/future CogentNexus namespaces are preserved.

## Deferred / non-guaranteed boundaries

v0.9.3 does not claim complete proof for:

- real abrupt power-loss/cold-boot continuation;
- OpenClaw versions newer than the validated `2026.7.1-2` baseline;
- high-concurrency/long-soak hardening;
- disk-full/database-corruption recovery;
- arbitrary exactly-once external side effects without a reconciliation contract.

These are deferred evidence boundaries, not reasons to rewrite the accepted behavior already proven for the implementation baseline and carried forward through explicit unchanged-surface proof.

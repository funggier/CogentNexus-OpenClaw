# CogentNexus v0.2.0

This release makes long, explicit OpenClaw requests durable before conversational
model inference begins. It also packages the verified lifecycle, recovery, and
continuation mechanisms from v0.1.0 as the new recommended release.

## Problems addressed

- Long multi-phase requests could remain tied to one conversation and appear to
  stop after interruption, Gateway recovery, or context compaction.
- Replaying the same durable intake could collide with an already initialized
  workflow instead of returning the existing owner-bound workflow safely.
- Generated component results lacked a deterministic built-in assembly step.
- The Windows supervisor could take up to five minutes to rediscover work and
  was less resilient while running on battery or after scheduler failure.
- Release documentation did not clearly distinguish durable continuation from
  ordinary conversation history.

## What changed

- A conservative pre-inference classifier recognizes explicit, multi-phase,
  numerically constrained, interruption-sensitive requests.
- Accepted requests are persisted outside the chat transcript and compiled into
  bounded, owner-bound workflow components before a conversational model runs.
- Original request files can be included in Ollama worker prompts without
  duplicating them into every generated instruction.
- A portable `concat` executor assembles verified component artifacts
  deterministically.
- Intake retries are idempotent for the same task and trusted owner; terminal
  workflows return their existing state rather than starting duplicate work.
- Internal continuation/subagent messages are excluded, and `#cogent-direct`
  remains an explicit escape hatch for direct conversational handling.
- The Windows supervisor interval is one minute, supports battery operation,
  and uses bounded restart-on-failure settings. Runtime cooldowns, retry budgets,
  PID fencing, and circuit breaking continue to prevent restart storms.

## Gateway and interruption recovery

CogentNexus keeps workflow state, ownership, validation evidence, and completion
delivery outside the transient model context. A recovered Gateway can rediscover
unfinished workflows, resume safe steps from checkpoints, and schedule one
idempotent completion turn back to the bound owner session. This reduces the
chance that completed work becomes silent after compaction or interruption.

Context compaction itself is still managed by OpenClaw. Very large system
instructions, recent messages, or individual tool outputs can still exhaust a
model context window; durable workflows and clean-session rotation protect task
continuity but do not enlarge the model context limit.

## Known WebChat presentation issue

After successful pre-inference admission, WebChat may display:

> Your message could not be sent: CogentNexus admitted this as durable workflow
> ... (blocked by cogentnexus-rotation)

The workflow can still be running normally. CogentNexus deliberately returns a
`block` decision after persisting and starting the owner-bound workflow so the
same request is not also sent to the conversational model. Current OpenClaw
versions prefix every blocked replacement message with `Your message could not
be sent`; they do not yet expose a separate `handled` or
`accepted-without-inference` result for this use case.

Check `.cogent/workflows/<workflow-id>/state.json` before retrying. A present,
owner-bound `running` workflow confirms successful admission. Investigate only
when the workflow is absent, or when its durable state and ledger report
`failed` or `blocked`. Resending only because of the WebChat wording is
unnecessary and can create a separate workflow for the repeated message.

Download the `v0.2.0` archive and `SHA256SUMS.txt` from GitHub Releases, verify
the archive, then run the platform installer. The installer updates the skill
and plugin, restarts Gateway unless explicitly skipped, and verifies health.

# CogentNexus-OpenClaw v0.9.8

Status: **development candidate — not yet published**

v0.9.8 is a terminal-authority and installer-compatibility bug-fix line for OpenClaw 2026.9.5. It prevents visible non-terminal Codex/App-Server progress from being mistaken for the durable Direct result, preserves native Ollama delivery behavior, and hardens candidate/install lifecycle boundaries discovered during physical qualification.

## Why this release exists

A real Dashboard Direct run on OpenClaw 2026.9.5 exposed a terminal-boundary defect:

1. the owner turn was durably admitted and routed Direct;
2. OpenAI/Codex emitted a visible progress/commentary assistant message;
3. that progress row carried `stopReason="stop"` even though the run continued into tool execution;
4. the old CNX transcript fallback could treat the visible row as the durable result;
5. the Ticket therefore became `response_ready`, delivered, and completed before the true final answer existed.

The production evidence proved that visible output and `stopReason="stop"` are not terminal authority.

For the Codex/App-Server mirrored path, the true terminal row carries:

- exact `__openclaw.runId`;
- `mirrorOrigin="codex-app-server"`;
- `__openclaw.runTerminal=true`.

Native Ollama terminal rows do not expose `runTerminal`, so the repair is deliberately mirror-specific rather than a global requirement.

## Exact terminal-final boundary

v0.9.8 fences the Dashboard Direct fallback as follows:

- an established `before_agent_finalize` candidate remains preferred;
- mirrored progress/commentary without `runTerminal=true` cannot stage the durable result;
- mirrored fallback staging requires the exact Ticket run id and owner session;
- a wrong or missing mirrored run identity cannot capture another Ticket;
- `stopReason="stop"` alone is never terminal proof;
- native/legacy provider paths without mirrored terminal metadata retain their existing proven fallback.

The resulting ordering is:

```text
accepted Ticket
  -> Direct route
  -> visible commentary/progress       [non-terminal]
  -> tool call / tool result           [non-terminal]
  -> exact mirrored runTerminal final
  -> response_ready
  -> durable Direct result
  -> delivery_confirmed
  -> completed
```

## OpenClaw 2026.9.5 plugin-mutation timeout reconciliation

Physical install-over qualification exposed a separate lifecycle behavior: `openclaw plugins enable|disable` can persist the requested mutation and then fail to exit before the existing 180-second timeout.

v0.9.8 does not convert arbitrary CLI failures into success. Only `subprocess.TimeoutExpired` enters bounded reconciliation:

1. read canonical `plugins.entries.cogentnexus-openclaw.enabled`;
2. regenerate the official plugin registry with `plugins registry --refresh`;
3. inspect the plugin with `plugins inspect --json`;
4. require config, refreshed registry, enabled/status state, and diagnostics to converge exactly;
5. otherwise re-raise the original timeout and remain fail-closed.

No OpenClaw SQLite row is edited directly.

## Dependency lifecycle isolation during candidate preparation

A later real install-over proved that plain `npm ci` could execute the development dependency `openclaw@2026.7.1-2` postinstall lifecycle and stall before CNX classification/first install mutation.

Candidate preparation therefore uses `npm ci --ignore-scripts` on the release/install surfaces that explicitly run their own CNX build/test/validation steps. This prevents unrelated peer/dev dependency lifecycle side effects while preserving deterministic lockfile installation.

Explicit CNX validation remains authoritative:

- `npm test`;
- `npm run evaluation`;
- `npm run plugin:validate`;
- `npm pack`.

## Upgrade compatibility

v0.9.8 explicitly recognizes an owned v0.9.7 installation as a supported in-place upgrade source. Existing ownership, PASSTHROUGH handoff, plugin fingerprint, rollover, and fail-closed checks remain intact.

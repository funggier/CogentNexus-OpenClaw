# v0.9.5 Plan 2 Session Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Centralize the physical-session generation rule so only a real ownership boundary can advance generation, while provider/model/runtime changes remain generation-neutral.

**Architecture:** `cnx_sessions` remains the single durable lifecycle authority. The new helper only decides whether an event represents a physical ownership boundary; it does not store sessions or create a second lifecycle source of truth. Existing deletion/recreation semantics remain authoritative in `v090.ts` and continue to use the tombstoned generation for the genuinely new lifecycle.

**Tech Stack:** TypeScript, Node `node:sqlite`, Vitest, existing CogentNexus-OpenClaw session ownership implementation.

**Spec:** `docs/superpowers/specs/2026-09-09-v0.9.5-architecture-repair-design.md` and `docs/superpowers/plans/2026-09-09-v0.9.5-delivery-session-identity-repair.md`

## Global Constraints

- `sessionKey + sessionId + generation` is lifecycle identity; `sessionKey` alone is not sufficient.
- Delete/replace/rotate are physical ownership boundaries.
- Provider change, model change, compaction, and Gateway restart do not advance generation when the physical session remains the same.
- No new session store may be introduced.
- Existing `v090.ts` remains the durable owner of `cnx_sessions`.
- Old lifecycle work must remain fenced after generation rotation.
- No release/tag/public-version mutation is part of this plan.

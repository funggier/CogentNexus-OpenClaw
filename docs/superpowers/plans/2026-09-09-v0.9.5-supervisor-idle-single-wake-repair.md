# v0.9.5 Supervisor Idle and Single-Wake Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Guarantee that healthy idle CogentNexus performs only cheap read-only classification and that each actionable recovery condition has exactly one durable wake owner.

**Architecture:** Replace broad boolean wake hints with a canonical `WakeDecision` classifier. The periodic Supervisor may still run, but it cannot invoke heavy reconciliation, provider recovery, config mutation, Gateway lifecycle, delivery retry, or inference retry without exact durable authority. Existing actionability fixes are preserved and consolidated.

**Tech Stack:** Python 3, SQLite, Windows Scheduled Task runtime, unittest, existing Host/Supervisor overlays.

**Spec:** `docs/superpowers/specs/2026-09-09-v0.9.5-idle-quiescence-and-single-wake-contract.md`; parent design `docs/superpowers/specs/2026-09-09-v0.9.5-architecture-repair-design.md`

## Global Constraints

- No actionable work -> no heavy wake.
- One exact durable work item -> one authoritative owner.
- Provider/model switch alone -> zero wake actions.
- Cloud attempt + stopped Ollama -> no Ollama probe/restart unless exact Ollama work exists.
- Durable final payload -> delivery recovery may wake; inference regeneration must not.
- Scheduler cadence is not itself a defect; false-positive actionability is.
- Idle diagnostics must not flood logs.
- Preserve terminal Ticket, generation, session-liveness, lease and delivery fences.

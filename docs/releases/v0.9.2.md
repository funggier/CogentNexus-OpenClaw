# CogentNexus v0.9.2 — development candidate

v0.9.2 is a Host/CLI/provider-layer release candidate built on the accepted v0.9.1 Recovery Core. It is **not tagged or released yet**.

## Scope

The v0.9.1 OpenClaw Bridge payload remains unchanged at package version `0.9.1`. v0.9.2 changes the external Host/control surface rather than rewriting Ticket admission, durable-result ownership, delivery fences, or exactly-once-ish result handling.

## Added

### Provider-neutral local lifecycle

CogentNexus can supervise either Ollama (`127.0.0.1:11434`) or LM Studio (`127.0.0.1:1234`). Both may be installed; MANAGED mode has exactly one durable `selectedProvider`.

```powershell
.\cnx.cmd start --provider ollama
.\cnx.cmd start --provider lmstudio
```

A successful verified selection is remembered. Later `start`/`restart` reuse it. There is no silent provider fallback.

### Transactional provider + OpenClaw route switch

Provider switching has coordinated durable/config/process boundaries:

1. durable `providerTransition` records intent before lifecycle mutation;
2. exact short-lived OpenClaw rollback copy protects config mutation;
3. target provider starts/verifies before a route-bearing Gateway boundary;
4. Gateway process reload is forced when required;
5. provider + Gateway + route are verified before commit.

v0.9.2 manages only:

- default local model route;
- LM Studio provider timeout;
- agent timeout;
- LM Studio llama.cpp unsupported tool-schema keywords.

Accepted v0.9.1 remains the sole CogentNexus owner of `diagnostics.stuckSessionAbortMs` in MANAGED mode.

### LM Studio llama.cpp compatibility profile

It passed minimal, `cron`, `image_generate`, combined `cron + image_generate`, and the full OpenClaw `coding` surface (26 tools in the observed run).

### Event-driven model/provider recovery

Live runtime logs proved a healthy LM Studio/llama.cpp request can remain silent to OpenClaw for more than 360 seconds while prompt prefill is still progressing. A widened watchdog allowed the same cold request to complete successfully at roughly 469 seconds wall time.

v0.9.2 therefore does **not** use elapsed lease age as recovery authority.

```text
provider/Gateway healthy + silent active call
    -> active_model_processing_unknown
    -> no restart / no re-inference

LM Studio prompt_progress
    -> active_model_processing
    -> proof of life
    -> no restart / no re-inference

provider_dead / provider_unreachable
    -> open durable provider incident
    -> bounded recovery authority

successful model_call_ended
    -> stable_success
    -> close incident
```

The old development-only `+600s` grace, recovery cooldown, and rolling-hour budget have been removed from recovery policy.

### LM Studio blocking provider-event adapter

While LM Studio is selected in MANAGED mode, v0.9.2 consumes:

```text
lms log stream --source runtime
```

as a blocking event stream. Prompt progress is persisted as suppression-only proof of life. If the stream ends, the adapter probes LM Studio; only a genuinely unreachable provider publishes `provider_dead` and wakes the Host immediately.

The adapter is stopped at the PASSTHROUGH boundary so disabled CogentNexus cannot react to later provider events.

### Per-incident recovery circuit

Automatic recovery is bounded by failure incident rather than wall-clock windows:

| Provider | Maximum automatic recoveries per incident |
| --- | ---: |
| Ollama | 3 |
| LM Studio | 2 |

Time passage never reopens the circuit. An incident closes only after stronger evidence such as durable successful model completion or a verified explicit/manual provider transition. A later failure opens a new incident generation.

### Event-authorized use of accepted v0.9.1 Recovery Core

The accepted v0.9.1 claim/quiesce/result-fence/recovery primitives remain unchanged. v0.9.2 suppresses the legacy periodic deadline from independently claiming a Direct call. When explicit provider-failure evidence intersects an active Direct model call, v0.9.2 makes the existing lease claimable at the failure-event timestamp and then invokes the accepted v0.9.1 recovery sequence.

Thus the **event** is recovery authority; the deadline is only reconciliation metadata.

### LM Studio request envelope

Verified v0.9.2-owned request fields:

```text
models.providers.lmstudio_local.timeoutSeconds = 1100 s
agents.defaults.timeoutSeconds                 = 1200 s
```

These prevent premature request/agent cancellation and are not circuit/recovery timers. Separately, accepted v0.9.1 moves OpenClaw's native stuck-session watchdog to a ~24-hour MANAGED compatibility fence and restores the operator's original value on PASSTHROUGH.

### Verified native/PASSTHROUGH Gateway boundary

`disable` no longer treats disk config restoration as enough. After the accepted v0.9.1 PASSTHROUGH transition, v0.9.2:

1. stops provider event adapters;
2. restores its route/request-timeout/schema-compat fields;
3. forces Gateway restart/start;
4. requires healthy post-boundary Gateway evidence.

`reset` and `uninstall` reuse that safety boundary and fail closed before destructive cleanup if native OpenClaw cannot be reloaded.

### Provider-aware install/reset

```powershell
.\scripts\install.ps1 -Provider ollama
.\scripts\install.ps1 -Provider lmstudio
```

```sh
./scripts/install.sh --provider ollama
./scripts/install.sh --provider lmstudio
```

Exactly one installed provider may be selected without an explicit flag. Fresh state with both installed requires an explicit provider. `reset` returns to fresh-install semantics and preserves the v0.9.1 explicit-`y`, PASSTHROUGH-first safety boundary.

## Recovery compatibility

Once explicit failure evidence makes a Direct call recovery-eligible, accepted v0.9.1 ordering remains authoritative:

1. quiesce Gateway/provider;
2. reconcile durable result/delivery fences while inference is impossible;
3. authorize at most one eligible Direct recovery;
4. restart selected provider/Gateway;
5. consume durable recovery authority.

Deterministic request-shape failures such as provider HTTP 4xx/schema/grammar rejection remain non-retryable and do not justify provider restart.

Process exit code or top-level wrapper status is not success proof; inner/durable completion evidence remains authoritative.

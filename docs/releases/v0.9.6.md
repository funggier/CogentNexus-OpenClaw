# CogentNexus-OpenClaw v0.9.6

## Release focus

v0.9.6 hardens same-session input serialization and authoritative user Stop semantics, converges current documentation, and adds the MIT License.

## Major runtime change — pre-dispatch FIFO ownership

Earlier CNX Stop handling could cancel durable Tickets correctly while OpenClaw's native follow-up queue still dequeued a successor turn. CNX then blocked that successor at `before_agent_run`, preserving zero inference but surfacing a user-visible `blocked by cogentnexus-openclaw` error.

v0.9.6 removes that race:

- later eligible same-generation owner input is durably persisted at `before_dispatch`;
- while an older Ticket remains non-terminal, the later request is held outside the Host queue;
- normal predecessor completion releases the original request with its original context;
- authoritative Stop advances owner generation once and cancels current + held Tickets;
- held cancelled ingress is consumed before Host queue admission;
- no successor Host run is created for the cancelled held message.

## Restart durability

If Gateway restart destroys an in-memory pre-dispatch waiter, accepted held ingress with `bound_run_id IS NULL` can be reconstructed into bounded recovery. Recovery remains FIFO-fenced behind older non-terminal ingress.

Active/bound predecessor runs remain owned by the existing Host/recovery reconciliation boundary and are not regenerated by this held-ingress mechanism.

## Final physical acceptance

The final CNX-442 Discord test ran against OpenClaw `2026.9.5 (ec9c1a1)` with `ollama/qwen3.8:27b` and context `24576`.

Observed:

- first Ticket entered one authoritative Host run;
- second Ticket was accepted and held with `bound_run_id = NULL`;
- second Ticket had zero model calls and zero inference attempts;
- user Stop advanced generation exactly once;
- both Tickets became `cancelled`;
- held Ticket stayed unbound with zero inference;
- Host trajectory contained one run only;
- the queued second user message never entered the Host transcript;
- no successor Host run was created;
- no new `blocked by cogentnexus-openclaw` / `This turn ended before a reply` error appeared;
- Gateway and Discord remained healthy after settlement.

## Upgrade/install-over compatibility

v0.9.6 explicitly recognizes an owned v0.9.5 installation as a supported upgrade source. This preserves fail-closed ownership validation while allowing the normal v0.9.5 -> v0.9.6 install-over path.

## Clean reinstall backup safety

The Windows clean-reinstall path no longer follows external reparse-point archive directories while backing up the active application-data root. This prevents T:-hosted historical backup junctions from being recursively copied into a new clean-reinstall backup while preserving the active local runtime/state backup and fail-closed ownership boundary.

## Documentation convergence

Current-facing documentation now distinguishes:

- current v0.9.6 source/release state;
- historical v0.9.5/v0.9.4 evidence;
- regression dependency pin versus latest physical compatibility evidence;
- current branch/task authority versus historical hard-coded coordination branches;
- retired watcher automation versus current explicit coordination.

The old Codex `CogentNexus coordination watch` automation is retired and is not part of the current workflow.

# CogentNexus v0.9.2

v0.9.2 is a Host/CLI/provider-layer release built on the accepted v0.9.1 Recovery Core.

## Scope

The v0.9.1 OpenClaw Bridge payload remains unchanged at package version `0.9.1`. v0.9.2 changes the external Host/control surface around that Bridge rather than rewriting Ticket admission, Direct Recovery classification, durable-result ownership, or delivery fences.

## Added

### Provider-neutral local lifecycle

CogentNexus can supervise either:

- Ollama (`127.0.0.1:11434`)
- LM Studio (`127.0.0.1:1234`)

Both may be installed on the same machine. CogentNexus supervises only the durable `selectedProvider`.

```powershell
.\cnx.cmd start --provider ollama
.\cnx.cmd start --provider lmstudio
```

A successful explicit start remembers the provider. Later `start`/`restart` reuse it.

### Durable provider transition

Provider switching writes a `providerTransition` marker before lifecycle mutation and commits `selectedProvider` only after provider + Gateway verification succeeds.

A power/process interruption during switching therefore leaves recoverable evidence rather than silently falling back to another provider.

### Aircraft-style pre-flight inspection

New read-only diagnostic namespace:

```powershell
.\cnx.cmd check system
.\cnx.cmd check system --provider lmstudio
.\cnx.cmd check provider
.\cnx.cmd check gateway
.\cnx.cmd check model
.\cnx.cmd check storage
.\cnx.cmd check recovery
.\cnx.cmd check delivery
.\cnx.cmd check resources
```

Full verdicts:

- `READY` (exit 0)
- `READY_WITH_WARNINGS` (exit 1)
- `NOT_READY` (exit 2)
- `INDETERMINATE` (exit 3)

All `check` commands are read-only and explicitly report that no state was changed.

### Provider-aware install/reset

Windows installer:

```powershell
.\scripts\install.ps1 -Provider ollama
.\scripts\install.ps1 -Provider lmstudio
```

POSIX installer:

```sh
./scripts/install.sh --provider ollama
./scripts/install.sh --provider lmstudio
```

If exactly one supported provider is installed, the provider option may be omitted. If both are installed on a fresh state, explicit selection is required.

`reset` returns to fresh-install provider semantics. With both providers installed:

```powershell
.\cnx.cmd reset --provider ollama
# or
.\cnx.cmd reset --provider lmstudio
```

The v0.9.1 explicit-`y`, PASSTHROUGH-first, verified reset/uninstall safety boundaries remain in force.

## Recovery compatibility

The accepted Direct model-call stall classifier remains unchanged. v0.9.2 translates the old concrete `--provider` lifecycle boundary to the selected provider adapter while preserving the order:

1. quiesce Gateway/provider;
2. reconcile durable result/delivery fences while inference is impossible;
3. authorize at most one eligible Direct recovery;
4. restart selected provider/Gateway;
5. consume durable recovery authority.

This release was motivated in part by native testing where the same local model/config/tool policy could stall in one run and complete normally in a later retry. See `docs/TRANSIENT_STALL_RECOVERY.md`.

## Versioning note

- CogentNexus Core/Host release: **0.9.2**
- OpenClaw Bridge package: **0.9.1**

The Bridge package remains 0.9.1 because its payload is unchanged. Repository/release validation now checks Core release version separately from the internally consistent Bridge package/manifest/lock version.

## Validation target

The release validation matrix covers Linux, Windows and macOS with Python 3.11/3.14, Python compilation, unit tests (including provider/check/lifecycle-translation tests), plugin tests/evaluation/audit/validation, installer syntax, baseline consistency and release packaging.

The accepted live provider baseline remains Windows + OpenClaw `2026.7.1-2` + Ollama. LM Studio lifecycle support is included in v0.9.2 but should receive an explicit local live acceptance run before claiming the same provider-specific operational confidence as the accepted Ollama baseline.

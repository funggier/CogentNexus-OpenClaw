# CogentNexus-OpenClaw v0.9.5

> Published release. The immutable `v0.9.5` tag and GitHub Release both target merge SHA `50be0b973c30fd8d1528aaac3497c0fc3b0b4d95`.

## Release status

`v0.9.5` is the current published stable baseline for CogentNexus-OpenClaw.

The release completed:

- final runtime acceptance;
- required OpenAI and Ollama provider-path validation;
- idle-quiescence verification;
- controlled actionable-wake verification with exactly one durable work item;
- exact-head release-gating CI verification;
- PR #38 merge verification;
- immutable tag verification;
- exact-tag post-release installation and runtime verification.

## Verified implementation changes

- CNX execution remains independent of the currently selected OpenClaw provider/model.
- OpenClaw retains ownership of provider, model, authentication route, and provider lifecycle for Cloud pass-through.
- CNX durable execution preserves Ticket/session identity across provider changes and gateway restarts.
- Canonical delivery/session identity rules fail closed for ambiguous receipt identity and stale session generation.
- Supervisor idle handling uses single-wake authority and rejects heavy work when there is no actionable durable work.
- The v0.9.5 installer uses the canonical `cnxclaw.py` facade and provider-neutral installer handling.
- PowerShell 5.1 npm stderr handling uses an explicit diagnostic boundary and exit-code validation.
- Post-install system-check state mapping preserves canonical controller state while exposing the expected managed/passthrough/maintenance semantics.
- Current operator naming remains namespace-isolated under `CogentNexus-OpenClaw` / `cnxclaw`.

## Provider contract

- **Ollama:** managed provider for health, lifecycle, and recovery; required and live-tested successfully.
- **OpenAI:** OpenClaw-owned Cloud/pass-through route; required for release acceptance and live-tested successfully.
- **LM Studio:** not required for the v0.9.5 release gate and not a current managed-provider contract.

CogentNexus-OpenClaw does not read, copy, persist, refresh, or log Cloud credentials and does not take ownership of Cloud provider lifecycle.

## Operational validation shape

The accepted execution path demonstrated:

```text
human intent
-> durable Ticket admission
-> logical session/run ownership
-> model execution
-> durable result
-> delivery confirmation
-> settled state
```

Controlled actionable wake preserved session/ticket/run identity, generation and ownership semantics, processed exactly one durable work item, and returned to idle without duplicate ownership.

## Known diagnostic discrepancy

The validated post-release host still exposes a narrow `cnxclaw.cmd check system` provider-selection diagnostic that can contradict the authoritative active runtime/provider status. This is recorded as a **known checker anomaly** and is not treated as proof that the v0.9.5 runtime is inactive.

It was intentionally not repaired after publication. Any correction must be made through a new development candidate and the normal validation/release process; the immutable `v0.9.5` release must not be modified.
